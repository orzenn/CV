**Какой метод где ошибся.** White-patch (p99) на этом кадре **ничего не сделал**: усиление во всех каналах равно 1.0. Алгоритм опирается на самые яркие пиксели, но на фото есть сильные белые блики и белый блок зарядки со значениями 255. Метод счёл их эталонным белым светом, хотя они обрезаны и не несут информации об оттенке лампы. Grey-world выровнял баланс (разброс средних упал), но его минус в том, что он считает серым *всю сцену*, а фон стола бежевый — в итоге часть реального тёплого оттенка столешницы тоже компенсировалась.

| Что | Значение |
|-----|----------|
| поворот 30° (`data/poster.jpg`): размер до → после, пустой холст | 1389 × 1000 → 1703 × 1561, 47.8 % |

| то же на `iu-building.jpg` (480 × 320) | 27.9 / 36.0 / 37.2 дБ (совпало с `sample_data/README.md`) |
| выпрямление `poster.jpg`: стороны в кадре, px | top 353.0 · right 945.9 · bottom 334.4 · left 679.4 |
| `--aspect` / размер выхода | 0.707 / 353 × 499 |
| `poster-angle.jpg` курса: совпадение с `poster-gt.png` | 99.1 % |

**Какой штрих погиб при ×0.25.** Высота строчной буквы в `text.jpg` после ×0.25 — всего несколько пикселей. В `naive` пропускаются тонкие перекладины («e», «a») и сглаженные засечки шрифта: буквы рассыпаются на отдельные пиксели, и PSNR сильно падает (25.2). В `area` и `blur` эти же штрихи не исчезают, а превращаются в светло-серую заливку: текст остаётся читаемым. 

**Почему `--aspect 0.707`.** Задан стандартный формат бумажного листа A4 (0.707). Брать размер по сторонам прямо в кадре нельзя: из-за сильной перспективы правая сторона таблички (945.9 px) почти в полтора раза длиннее левой (679.4 px). Если вычислять пропорции по ним, итоговое изображение получилось бы неестественно вытянутым.

## 2. Три вопроса

**2.1. Какое цветовое пространство выбрано для хромакея и почему? Что было бы в RGB?**

HSV: оттенок H и насыщенность S описывают цвет, а освещённость вынесена в V, который по умолчанию открыт (≥ 40). Поэтому один бокс H, S ловит предмет и на свету, и в тени. В RGB яркость меняет сразу все три канала одновременно, цвет предмета образует вытянутое по диагонали облако, и бокс, параллельный осям, либо слишком широк (захватит фон), либо не попадает в тени. На моём желе HSV-маска (H 8–32 при S ≥ 30) дала 10.38 % кадра и цельный объект.

**2.2. Что происходит с гистограммой при γ < 1 и при γ > 1? Куда деваются обрезанные пиксели?**

`dark.jpg`, γ = 0.5: масса гистограммы уходит вправо (среднее 71.1 → 127.0, медиана 58 → 119), тени растягиваются. На графике видна «гребёнка»: из 256 входных уровней часть сливается, образуя провалы. γ = 2.0: масса прижимается к нулю (среднее 28.1, медиана 16), тени сжимаются в сплошной черный, чёрных пикселей становится 3.22 % вместо 1.90 %. Обрезанные пиксели никуда не исчезают: они жестко приравниваются к 0 или 255, складываясь в один крайний столбик на гистограмме, а различия между ними теряются необратимо.

**2.3. Почему CLAHE лучше `equalizeHist` на вашем фото — по числам из 1.3?**

На `dark.jpg` `equalizeHist` сработал хуже: он строит одну кривую на весь кадр, и из-за доминирующей яркой стены слишком сильно её осветлил (света: 133.7 → 224.2), сделав тени еще темнее (с 31.0 до 23.2). CLAHE считает кривую локально по плиткам 8 × 8 и ограничивает пересветы (clip 2.0). В результате CLAHE вытащил детали из темноты (среднее в тенях выросло до 46.0, а σ увеличилась с 15.2 до 23.5), сохранив при этом нормальную текстуру в светах (148.2).

## 3. Где сломалось

**Команда:** `python photolab.py chromakey data/object.jpg --bg data/bg.jpg --sample 350,350,50,50 -o out/object_on_bg.jpg --mask out/object_mask.png`  
**Файл:** `data/object.jpg`  
**Что получилось:** Маска разорвалась на бликах и захватила куски фона (чёрную клавиатуру и серый корпус ноутбука).  
**Причина:** Прямоугольник `--sample` промахнулся мимо чистого оранжевого цвета желе и захватил полупрозрачную упаковку. У серых пикселей насыщенность S близка к нулю, а оттенок H может быть любым. В итоге алгоритм расширил цветовой диапазон и вырезал лишнее.  
**Что помогло:** Задание координат прямоугольника строго в центре чистого цвета объекта без бликов: `--sample 500,500,100,100`.

Всё, что лежит в `out/`, получено этими командами:

```bash
python photolab.py resize photo.jpg --scale 0.4 -o data/photo.jpg

python photolab.py wb data/bright.jpg --method white-patch -o out/bright_wp.jpg
python photolab.py clahe data/dark.jpg --clip 2 --tiles 8 -o out/dark_clahe.jpg --compare out/dark_cmp.jpg --hist out/dark_clahe_hist.png
python photolab.py chromakey data/object.jpg --bg data/bg.jpg --sample 500,500,100,100 -o out/object_on_bg.jpg --mask out/object_mask.png
python photolab.py rotate data/poster.jpg --deg 30 -o out/poster_rot30.jpg
python photolab.py resize data/text.jpg --scale 0.25 --report -o out/text_x025.jpg
python photolab.py rectify data/poster.jpg --clicks --aspect 0.707 -o out/poster_front.jpg
python photolab.py sheet data/dark.jpg data/bright.jpg data/object.jpg data/bg.jpg data/poster.jpg data/text.jpg out/dark_g05.jpg out/dark_g2.jpg out/bright_gw.jpg out/bright_wp.jpg out/dark_clahe.jpg out/dark_cmp.jpg out/object_on_bg.jpg out/poster_rot30.jpg out/text_x025.jpg out/poster_front.jpg --cols 4 -o out/sheet.jpg
```
